# Known Technical Debt — Governance Operations

Recorded per DEBT-020 while hardening the engine (PR #4). Owner: engineering governance maintainers.

| ID | Debt | Impact | Planned resolution |
|---|---|---|---|
| DEBT-GOV-001 | RESOLVED. The CLI cast the governance pack without schema validation and crashed on malformed packs. | Uncontrolled crash on malformed packs. | Resolved on main (PR #1): the CLI validates the pack against the schema and the engine rejects semantically invalid packs, exiting with a diagnostic. |
| DEBT-GOV-002 | PARTLY RESOLVED. Exceptions are evaluated (scope, metadata, time window, requester must differ from approver). An approver-authority policy (`model/authority/`) now models EXC-021 section 15's roles by severity, and the engine lets a P1 waiver or P1 risk acceptance hold when the approver holds an APPROVED role that covers it. P0 never holds. Every role in the v0.1 policy is DRAFT with unassigned holders, so nothing is enforced yet and P1 waivers still do not hold. | P1 waivers still blocked until roles are approved. | Leadership approves roles and names holders (and settles the EXC-021 versus blueprint conflict over who approves P1). Remaining gap: the check verifies a claimed identity, it does not authenticate it, so exception records need independent review or signed approvals. Not modelled: the additional security authority and PRD-018 visibility (EXC-021 section 15). |
| DEBT-GOV-003 | RESOLVED. An empty pack, or one where no control applies, evaluated to GO. | Vacuous GO. | Resolved: `deriveDecision` returns NO-GO with `SCOPE:NO_APPLICABLE_CONTROLS` when no control is applicable (GOV-022 section 10). A dedicated "not evaluated" state remains an option if leadership wants one. |
| DEBT-GOV-004 | RESOLVED. OPEN P2/P3 risks did not appear in the decision. | Lost visibility. | Resolved on main (PR #1): unresolved P2/P3 risks appear as `RISK:<id>` warnings and give GO_WITH_CONDITIONS. Owner and due-date fields on conditions (GOV-022 section 9) are not yet modelled. |
| DEBT-GOV-005 | `hasPythonDependency` regex-scans the whole manifest; comments, keywords and project names can yield false framework signals. | Noisy applicability signals. | Parse `pyproject.toml` / `requirements.txt` dependency tables. |
| DEBT-GOV-006 | RESOLVED. No lockfiles; CI installed with caret ranges. | Builds can drift. | Resolved on main (PR #1): lockfiles committed and CI uses `npm ci`. GitHub Actions are pinned to commit SHAs (checkout v7.0.1, setup-node v7.1.0); update the pins deliberately when new releases are reviewed. `npm audit` reports 0 vulnerabilities in the engine, analyzer and CLI as of 2026-11-17 (vitest was upgraded to 5.x; the CLI's `fast-uri` was bumped to 3.1.9). New advisories will recur, so this is checked, not closed for good. |
| DEBT-GOV-007 | The matrix test's oracle restates the engine's policy predicates, so a policy error shared by both would pass. The hand-written case table is the independent evidence. | Reduced test independence. | Review the policy table with the governance owner; add multi-control cases. |
| DEBT-GOV-008 | Schema evidence requirements tightened without a schema version bump. | Older packs lacking `source`/`freshness`/`supports_controls` stop validating (they already evaluated as missing evidence in the engine). | Version the schema when it is next changed. |
