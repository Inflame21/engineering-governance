# Known Technical Debt — Governance Operations

Recorded per DEBT-020 while hardening the engine (PR #4). Owner: engineering governance maintainers.

| ID | Debt | Impact | Planned resolution |
|---|---|---|---|
| DEBT-GOV-001 | RESOLVED. The CLI cast the governance pack without schema validation and crashed on malformed packs. | Uncontrolled crash on malformed packs. | Resolved on main (PR #1): the CLI validates the pack against the schema and the engine rejects semantically invalid packs, exiting with a diagnostic. |
| DEBT-GOV-002 | PARTLY RESOLVED. Exceptions are evaluated (scope, metadata, time window, requester must differ from approver). An approver-authority policy (`model/authority/`) now models EXC-021 section 15's roles by severity, and the engine lets a P1 waiver or P1 risk acceptance hold when the approver holds an APPROVED role that covers it. P0 never holds. Every role in the v0.1 policy is DRAFT with unassigned holders, so nothing is enforced yet and P1 waivers still do not hold. | P1 waivers still blocked until roles are approved. | Leadership approves roles and names holders (and settles the EXC-021 versus blueprint conflict over who approves P1). Remaining gap: the check verifies a claimed identity, it does not authenticate it, so exception records need independent review or signed approvals. Not modelled: the additional security authority and PRD-018 visibility (EXC-021 section 15). |
| DEBT-GOV-003 | RESOLVED. An empty pack, or one where no control applies, evaluated to GO. | Vacuous GO. | Resolved: `deriveDecision` returns NO-GO with `SCOPE:NO_APPLICABLE_CONTROLS` when no control is applicable (GOV-022 section 10). A dedicated "not evaluated" state remains an option if leadership wants one. |
| DEBT-GOV-004 | RESOLVED. OPEN P2/P3 risks did not appear in the decision. | Lost visibility. | Resolved on main (PR #1): unresolved P2/P3 risks appear as `RISK:<id>` warnings and give GO_WITH_CONDITIONS. Owner and due-date fields on conditions (GOV-022 section 9) are not yet modelled. |
| DEBT-GOV-005 | `hasPythonDependency` regex-scans the whole manifest; comments, keywords and project names can yield false framework signals. | Noisy applicability signals. | Parse `pyproject.toml` / `requirements.txt` dependency tables. |
| DEBT-GOV-006 | RESOLVED. No lockfiles; CI installed with caret ranges. | Builds can drift. | Resolved on main (PR #1): lockfiles committed and CI uses `npm ci`. GitHub Actions are pinned to commit SHAs (checkout v7.0.1, setup-node v7.1.0); update the pins deliberately when new releases are reviewed. `npm audit` reports 0 vulnerabilities in the engine, analyzer and CLI as of 2026-11-17 (vitest was upgraded to 5.x; the CLI's `fast-uri` was bumped to 3.1.9). New advisories will recur, so this is checked, not closed for good. On 2026-11-18 a new `picomatch` ReDoS advisory (GHSA-fc5q-39xc-vjpf, high) appears in all three packages through the vitest/vite test-runner chain; it is development-only and not part of the shipped plugin bundle, and no fix is available without a breaking vitest change. Also, `analyzer/package.json` and `engine/package.json` declare `@types/node` twice (the CLI's duplicate was collapsed when esbuild was added). |
| DEBT-GOV-007 | The matrix test's oracle restates the engine's policy predicates, so a policy error shared by both would pass. The hand-written case table is the independent evidence. | Reduced test independence. | Review the policy table with the governance owner; add multi-control cases. |
| DEBT-GOV-008 | Schema evidence requirements tightened without a schema version bump. | Older packs lacking `source`/`freshness`/`supports_controls` stop validating (they already evaluated as missing evidence in the engine). | Version the schema when it is next changed. |
| DEBT-GOV-009 | A WARN tool result maps to `PARTIALLY_VERIFIED`, which the engine does not accept as proof of a control, so a control linked to WARN evidence is UNVERIFIED and blocks (NO-GO), although the WARN definition says "non-blocking". No adapter produces WARN yet and current adapters link no controls, so this is latent. | Scanner results (ADR-0001) would block a linked control on any low-severity warning instead of giving conditions. | Governance owner chooses an option in ADR-0001 section 5 before scanner evidence is linked to a control; then change the policy with decision-matrix tests under CODEOWNERS review. |
| DEBT-GOV-010 | The OSV-Scanner, Gitleaks and Semgrep adapters have not run against real tool output; their fixtures are hand-written from the vendors' documentation. OSV-Scanner: reads an assumed `database_specific.severity` label, cannot record the advisory-data date or tell runtime from development dependencies. Gitleaks: a finding has no file or line because the adapter reads only exit codes; a shallow clone limits the history scanned. Semgrep: the shape of `errors[]` is undocumented, so only its count is used; no rule set exists in any repository, so the check is UNSUPPORTED everywhere today; inline `nosemgrep` suppressions cannot be counted. All three resolve the tool through `PATH`, the runner does not forward proxy variables, and output over the runner's 2 MB buffer reports ERROR. Whether a binary placed in a scanned repository could be picked up by Windows path resolution has not been checked, as with the existing Python check. | Possible false P1s or ERROR on real repositories; reduced evidence of data freshness; untrusted-repository exposure not assessed. | Capture real output and replace the fixtures; fix the severity source; record the advisory snapshot; author a reviewed Semgrep rule set; check executable resolution for untrusted repositories; revisit proxy handling and buffer size. |
| DEBT-GOV-011 | Secret scanning uses Gitleaks, which is feature-complete (security patches only); its successor Betterleaks is unverified. Gitleaks does not document the output channel or redaction of its JSON report, so the adapter reads exit codes only (ADR-0001). | A frozen rule set will age; findings cannot point to a location. | Re-evaluate Betterleaks once its behaviour, licence and validation feature are verified; add locations only after redaction is verified in captured real output. |
| DEBT-GOV-012 | The Claude Code plugin (`plugins/engineering-governance`) has not run in a live Claude Code session: its manifests pass `claude plugin validate` and its bundled CLI is tested from a clean directory, but substitution of `${CLAUDE_PLUGIN_ROOT}` and `$ARGUMENTS` in the command skills, and the shell injection that runs the CLI, were not observed. The committed `bundle/governance.mjs` is a generated artifact (a freshness test guards it) built with esbuild 0.28.2, whose install script is not approved under npm's allowScripts policy (the bundler works without it). The repository is under a custom license (`LICENSE`: use and modify for own use, no redistribution), which is not OSI open source and has not had legal review; its text was drafted from the owner's stated terms without legal advice. The bundle is not signed or provenance-attested. | A command may fail until the substitution is confirmed; the licence needs a lawyer's read before reliance; the bundle's provenance rests on the repository alone. | Run each command once in a live session and fix any substitution problem; have the licence reviewed, in particular its no-redistribution clause against how adopters copy templates and fork on GitHub; decide on release tagging and provenance before publishing. |
